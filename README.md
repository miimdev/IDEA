# ایده‌پردازان | Idehpardazan

وب‌سایت دو‌زبانهٔ یک استودیوی خلاقیت؛ با طراحی تاریک، محتوای فارسی و انگلیسی، تجربه‌های تعاملی و مسیرهای سازگار با GitHub Pages. سایت بدون فریم‌ورک یا مرحلهٔ build ساخته شده است.

- **نشانی در نظر گرفته‌شده برای GitHub Pages:** https://miimdev.github.io/IDEA/ — انتشار فعلاً در انتظار مجوز Pages است (خطای 403). پیش‌نمایش موقت از پنل Arena در دسترس است.
- **مخزن و شاخهٔ کار:** https://github.com/miimdev/IDEA/tree/arena/b0b6b9a3-idea
- **پروژهٔ Supabase:** https://supabase.com/dashboard/project/jmpwryddrxmuwzmbmhsb

> **محتوای نمایشی:** پروژه‌ها، تصاویر، آمار، نام اعضای تیم، مشتریان و نظرات نمونه‌اند و نباید به‌عنوان سوابق واقعی منتشر نهایی شوند. راه ارتباطی، ایمیل و حساب‌های اجتماعی واقعی ارائه نشده‌اند؛ برای جلوگیری از ارسال پیام به نشانی اشتباه، این موارد خالی هستند.

## فناوری و ساختار

- HTML5 معنایی، CSS با متغیرها، Grid و انیمیشن، و JavaScript ES Modules؛ بدون framework و bundler.
- GSAP 3.12.5 و ScrollTrigger، Lenis 1.1.20 و Three.js 0.170.0؛ نسخه‌های مشخص‌شده در `assets/vendor` برای پایداری محلی قرار دارند و نشانی‌های CDN نسخه‌دار به‌عنوان پشتیبان استفاده می‌شوند.
- فونت‌های Vazirmatn و Inter با `font-display: swap` و نسخهٔ محلی بهینه‌شده؛ تصاویر WebP و بارگذاری تنبل.
- `css/`: توکن‌ها، پایه، کامپوننت‌ها، حرکت‌ها و صفحات. `js/`: پیکربندی عمومی، دادهٔ محلی، ترجمه، اسکرول، صحنهٔ ۳بعدی، کرسر، گذارها و منطق صفحات.
- `supabase/migrations/` و `supabase/seed.sql`: ساختار و داده‌های نمونهٔ دو‌زبانه. `assets/`: تصاویر اصلی، فونت‌ها، کتابخانه‌های نسخه‌دار و مجوزهای مربوط.
- صفحه‌های مستقل برای خانه، خدمات، نمونه‌کار، جزئیات پروژه، درباره، مجله/مقاله، تماس و ۴۰۴. مسیرها نسبی هستند؛ `.nojekyll` برای Pages موجود است.

## اجرا در محیط توسعه

به دلیل ES Modules باید فایل‌ها از یک سرور HTTP ارائه شوند، نه از مسیر `file://`:

```sh
python3 -m http.server 8000
# http://localhost:8000/
```

هیچ build یا نصب وابستگی برای اجرای سایت لازم نیست. در صورت قطع Supabase، محتوای `js/data.js` نمایش داده می‌شود و فرم‌ها به‌جای اعلام موفقیتِ نادرست، پیام خطا نشان می‌دهند.

## Supabase و امنیت

پروژهٔ مستقل متصل دارای ۸ پروژه، ۴ خدمت، ۶ مقاله، ۴ عضو تیم، ۵ نظر و ۸ مشتریِ نمونه است. RLS برای هر هشت جدول فعال است: جداول محتوا قابل خواندن عمومی‌اند؛ پیام‌ها و اشتراک‌ها فقط امکان INSERT عمومی دارند و SELECT عمومی آن‌ها بسته است. محدودیت طول، اعتبارسنجی و honeypot در فرم و پایگاه داده پیش‌بینی شده‌اند. برای مشاهدهٔ پیام‌های واقعی از پنل Supabase و حساب مجاز استفاده کنید.

`js/config.js` فقط URL پروژه و **کلید عمومی anon** را دارد؛ این کلید برای مرورگر طراحی شده و مجوزهای آن توسط RLS محدود می‌شود. هیچ‌گاه کلید `service_role` یا کلید محرمانه را در فرانت‌اند یا مخزن نگذارید. فایل `.env.example` صرفاً قالبی بدون کلید واقعی است. برای اتصال پروژه‌ای دیگر، migration و seed را فقط پس از بررسی تداخل نام جدول‌ها روی یک پروژهٔ اختصاصی اعمال کنید؛ سپس URL و کلید عمومی همان پروژه را در `js/config.js` قرار دهید.

برای انتشار نهایی، `studioEmail` و آدرس شبکه‌های اجتماعی در `js/config.js` باید با اطلاعات واقعی و تأییدشده جایگزین شوند. محتوای نمونه و آمار نیز باید جایگزین شوند. برای مقابله با حجم بالای اسپم در محیط عملیاتی، محدودسازی نرخ در لایهٔ سرور/Edge نیز توصیه می‌شود؛ honeypot به‌تنهایی تضمین ضداسپم نیست.

## حرکت و دسترس‌پذیری

لودر یک‌بار در هر session، ورود کلمه‌ای، لنز و tilt کارت‌ها، دکمهٔ magnetic، کرسر اختصاصی برای ماوس، مارکی و حلقهٔ واکنش‌پذیر به سرعت اسکرول، Three.js با نور و متریال شیشه، parallax، توقف رندر خارج از دید، اسکرول افقی pinned، فیلتر FLIP، شمارنده‌ها، خط فرایند، اسلایدر کشیدنی، انتقال صفحه، progress مقاله و تیک موفقیت فرم پیاده‌سازی شده‌اند. نسخهٔ بدون WebGL، بدون JavaScript و `prefers-reduced-motion` محتوای اصلی را حفظ می‌کنند. جهت و ترجمه با FA/EN تغییر می‌کند؛ فوکوس کیبورد، برچسب‌ها و ساختار معنایی در نظر گرفته شده‌اند.

## آزمون‌ها

`node tests/static.mjs` بررسی مستقل فایل‌ها و داده‌ها را اجرا می‌کند. آزمون‌های مرورگر شامل اندازه‌های ۳۲۰ تا ۱۹۲۰ پیکسل، هر دو جهت، فیلتر، منو، صفحهٔ پروژه و مقاله، فرم‌ها، کاهش حرکت، نبود WebGL و نبود JavaScript بوده‌اند. migration و سیاست‌های RLS علاوه بر پایگاه دادهٔ واقعی، در PostgreSQL محلی سازگار نیز آزموده شده‌اند. برای آزمون مرورگر اختیاری، `tests/browser.mjs` به Playwright نصب‌شده در محیط توسعه و یک سرور HTTP نیاز دارد. در آزمون محلی Lighthouse صفحهٔ خانه، Accessibility و SEO و Best Practices هرکدام ۱۰۰ شدند؛ امتیاز Performance به‌دلیل ناتوانی مرورگر هدلس محیط آزمون در ثبت screenshot trace محاسبه نشد و هدف ۸۵ هنوز تأیید نشده است.

## استقرار

گردش‌کار `.github/workflows/pages.yml` در هر push همین شاخه، فایل‌های استاتیک را بررسی و به‌صورت artifact با GitHub Actions منتشر می‌کند؛ شاخهٔ جداگانه‌ای برای انتشار ساخته نمی‌شود. برای استقرار، GitHub Pages باید قبلاً در تنظیمات مخزن با منبع «GitHub Actions» فعال شده باشد. فعال‌سازی اولیه با اتصال فعلی GitHub خطای مجوز 403 داد و نیازمند دسترسی مدیریت Pages است. برای دامنه یا مسیر جدید، `siteUrl` در `js/config.js` و نشانی‌های canonical/OG در HTML را به‌روزرسانی کنید.
